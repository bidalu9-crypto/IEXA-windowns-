# 真实模型桌面自主操作验收

用户目标：以 Codex 式目标驱动工作流为参照，让当前模型自主观察、操作电脑、核对结果并处理失败。此验收使用相同的能力维度，不把固定脚本成功等同于模型自主成功，也未测量 Codex 的对照成绩。

2026-11-10 续测、当前修复及最终结果见 `desktop-autonomy-20261110.md`。独立后端轮次使用正式包的 server/provider/runtime 和实际外部应用，上限 60 次工具调用、8 分钟。本文后面的 2026-11-09 结果保留为历史失败记录。

最新完整任务 `desktop-autonomy-20261110/model-1794270908690` 已通过：当前模型 46 次调用、约 6 分 3 秒完成 Chrome 下载、Explorer 重命名、WPS 编辑保存后重新打开；独立文件/操作顺序/截图及清理 13 项判据通过，重开截图已直接核对。峰值工作负载 RSS 938,668,032 bytes；无本轮新增残留，运行前已存在的后台进程另列保留。该结果不外推为所有应用或已完成 Codex 同题对照。

## 验收方法

当前所选模型通过正式 `/api/chat`、AgentRuntime、provider 和 `desktop_control` 执行，只提供业务目标与测试范围，不提供点击序列。临时 Bot 工具白名单仅含桌面工具，因此不得通过文件写入工具或脚本代替应用操作。独立进程只创建夹具、记录证据、读取最终文件并检查清理；CDP 用于同源验收启动和只读结果检查。

任务：Chrome 浏览网页并下载随机 Reference 的 RTF，Windows 资源管理器重命名，WPS 修改 STATUS，保存并重新打开核对。随机文件内容和 SHA256 由外部读取验证。每轮最多 40 次工具调用、7 分钟；停止确认单独记录。

受现有资源预算约束，真实模型轮次使用隐藏正式 IEXA 后端和最小已认证同源页面，释放聊天 UI 的测试占用；这不是完整聊天窗口与多应用同时可见的内存验收。IDE 的真实可见发布包验收单独记录。

## 已发现并修复的问题

1. 发布版 native helper 发现遗漏 `resources/app`，模型思考超过 30 秒后助手正常空闲回收，随后的启动持续报缺失。改为从实际已加载模块定位应用根，普通与隔离桌面共享解析；用户工作目录不再决定 helper 版本。
2. Chrome 有主窗口仍启用的已拥有弹窗，旧策略仅识别禁用拥有者的模态窗。新增短时、一次性输入后授权、完整拥有链及进程身份验证，返回只限已记录原拥有者。
3. 非 index HTML 预览、残留二进制错误、Monaco 总行数及整段粘贴问题详见 `ide-preview-entry-acceptance.md`。
4. 启动应用传入文档/目录参数时，旧逻辑可能直接激活已有窗口而丢弃参数。现在参数实际传给应用；Explorer 打开目录或 Home 时不走直接复用，窗口及后续转移均验证文件夹类和 Explorer 进程，排除桌面外壳及同名其他进程。

助手路径回归 `helper-regression/result.json`：编译与 25 项通过。启动/窗口策略回归 `launch-final-regression/result.json`：125 项通过，1 项需显式启动应用的旧测试跳过。真实包 `helper-startup-1794227461160/report.json`：冷启动、30 秒空闲后重启、隔离助手启动 3/3 通过；普通助手 executablePath 均为当前包内路径。该轮不操作应用窗口。

## 结论更新规则

以最后实际运行结果为准，保留较早失败。普通桌面、隔离桌面、固定脚本、真实模型、隐藏后端和可见 UI 分别陈述。有限应用验收不证明任意应用、系统权限界面或所有电脑操作；未实测部分明确标记。
