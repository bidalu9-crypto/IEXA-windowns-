## 变更与证据

### E1：并发会话空白

`src/renderer/app.js` 的 `switchSession` 原来以 `sessionRuntimes.has(id)` 判断历史缓存是否完整。历史请求尚未返回时，`setProcessing(false)` 已建立一个空 runtime。执行 A → B（历史延迟）→ A → B 后，第二次进入 B 会挂载空 fragment，不再请求历史。

现在使用显式 `historyReady`：未加载记录展示加载状态，失败展示可点击重试；迟到的成功/失败响应受视图版本和会话 ID 校验约束。新建会话仅在成功、且导航意图仍有效时转移当前 DOM；新建失败保留原历史请求。嵌套后台回调恢复进入时的 DOM 目标，后台写入不借用前台聊天区域。

`tests/browser-session-concurrency.test.js` 使用真实 Chromium 页面和可控网络夹具覆盖：
- 未加载缓存重入、迟到历史、迟到失败、当前历史失败重试；
- 新建请求延迟、切走后新建返回、新建失败不打断历史；
- 嵌套前后台更新，以及 A/B 两条 ReadableStream 经真实 SSE 解析/合批渲染链路同时输出；
- 连续切换，B 先结束、A 在后台继续并结束，无串话与空白。

### E2：本轮文件修改汇总卡

`src/renderer/services/FileChangeSummary.js`、`src/renderer/app.js`、`src/renderer/workbench.css`：
- 单张卡片显示“已编辑 N 个文件”、总增删行数、逐文件路径与统计；
- 同一路径多次修改按首次 before 与末次 after 汇总，普通差异使用行级 LCS / Myers；
- “审查”显示记录中的真实差异，保留上下文，长差异分页；文本不作为 HTML 执行；
- “撤销”调用真实后端，不是资源管理器预览按钮的改名；浅色、深色和移动窄屏均验证。

`src/main/session/FileChangeUndo.ts`、`src/main/tools/FileWriteLocks.ts`、`src/main/tools/ToolExecutors.ts`：
- 回滚选择依据是会话 ID + 稳定 turn ID，以及服务器保存的成功工具记录；不接受客户端提供的路径或旧内容；
- 回滚前校验整个文件集合的路径范围、记录链及当前 SHA-256；后续修改触发冲突，不覆盖；
- 保留原始字节与“原文件是否存在”，区分新建文件、空文件，恢复支持 BOM/CRLF/非 UTF-8 原字节；
- 文件工具跨会话共享写锁，撤销复用同一锁；已恢复路径逐项持久化，重复点击幂等；
- 任务执行中、低权限移动设备、范围变更、路径重定向及不完整旧记录均不执行撤销。

边界明确：汇总来自 `file_write` / `file_edit` 成功返回的结构化记录，不凭 shell 输出猜测文件变更。单个文件的前/后内容任一超过 512 KiB 时不保存自动撤销快照，卡片说明原因；旧记录不补造快照。预览超过 120000 字符会截取，截取记录的多次修改统计明确标注为累计。极大、复杂差异触及计算上限时显示按块替换统计，不声称最小差异。外部编辑器不共享进程内锁，文件替换前再次校验；这不是操作系统级跨进程文件事务。遇到中途 I/O 故障，返回已经恢复的路径，保留逐文件进度。
