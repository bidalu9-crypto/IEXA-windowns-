# 2026-09-17：窗口外观修正与可读性设置

基线：`61c2ddcfce1aafca871706c552100a5ba8de85fb`。本次修正上一版圆角导致经典系统标题栏的问题，并实现用户新增的字体/SVG 图标大小设置。

## E1：外观 → 字体大小 / SVG 图标大小

- 字体大小 100%–180%，每档 10%；界面 SVG 图标大小 100%–160%，每档 10%。
- 两个选项独立：不是整体网页缩放。字体选项不放大图标，图标选项不缩放字体、图片、文件预览。
- 输入立即预览，百分比同步显示；原生 range 支持键盘方向键，提供文字标签、当前值及说明。
- “恢复默认大小”将两个选项都还原为 100%，不重置主题色、明暗模式或其他配置。
- 大文字/图标下允许按钮、侧栏和输入区增长；保留工具入口，窄屏省略面包屑次要内容和按钮文字。
- 后端独立校验两个数值并写入 `.iexa-appearance.json`；旧设置缺少字段时使用 100%。浏览器 localStorage 作为本地回退；Electron 首次绘制前应用已保存的设置。

实现：`UiScale.js`、`InitialAppearance.js`、`app.js` 外观逻辑、`server.ts` 外观设置规范化，以及原有 CSS 字号参数化。使用原有字体家族，代码仍保持等宽字体。

验证：`tests/browser-accessibility-scale.test.js` 经真实 Chromium 与后端验证独立缩放、磁盘文件、刷新恢复、键盘操作、重置、服务端范围约束、深浅主题，以及 900/390 像素布局。`tests/ui-scale.test.js` 覆盖首次绘制、旧配置、非法值与存储异常。100% 基线继续通过原有按钮几何测试。

## E2：去掉经典系统外框，窗口栏融入工作台

上一版验收不足：只检查了 Win32 区域的圆角点，没有检查完整原生窗体截图；用户截图证实仍存在蓝色经典标题栏。

本次 Windows 主窗口使用不带原生标题栏的窗口，并将最小化、最大化/还原、关闭整合到原有顶部工具栏。Windows 10 关闭额外原生厚边框，使形状区域与实际界面尺寸一致；恢复窗口使用 12 DIP 圆角，最大化和全屏移除裁剪。Windows 11 保留原生 DWM 的圆角路线。

- 原有标题栏拖拽区域由 Electron 原生 hit-test 处理，交互按钮处为 no-drag。
- 显式提供边缘缩放后备处理，主进程读取实际鼠标位置、限定最小/最大尺寸；关闭仍走原来的后端退出流程。
- preload 只暴露限定窗口命令/缩放请求，沿用顶层可信页面校验，并再次限定主窗口 webContents；辅助窗口不获得主窗口控制权。
- 保留 `nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`。
- Windows 10 的无厚边框路径会发出全屏事件而原生 widget 查询值滞后，因此按真实 enter/leave 事件维护状态，不依赖过时查询值。

`scripts/check-window-chrome.cjs` 启动隔离临时工作区中的真实 Electron/本地后端，使用 `scripts/fixtures/capture-window-chrome.ps1` 的 Win32 `PrintWindow` 捕获完整窗口。图片只按真实窗口 region 裁切并将 region 外的角设为透明，没有重绘/模拟标题栏。

- client 尺寸等于整体窗口尺寸，没有额外系统标题栏或厚边框；四角在真实区域外。
