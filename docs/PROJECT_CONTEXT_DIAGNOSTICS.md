# 项目范围与提示词诊断

## 使用位置

重启当前源码运行的 IEXA，打开「灵魂」页面：

- **项目测试范围**：先打开项目，填写测试目标、允许操作（每行一项）及背景/排除项，再保存。目标和操作需同时填写；同时清空可移除范围。按项目真实路径分别持久保存，不写入项目源码。切换项目后重新加载；旧页面提交到其他项目时返回 409，不会误覆盖。
- **实际提示词诊断**：先选择会话，点「启用下一次采集」，回到该会话发送消息，再点「读取预览」。没有启用时不采集。支持手动清除。

## 数据与行为边界

范围设置是用户声明的任务背景，不是授权校验器或工具访问控制。只复用明确列出的目标和操作，不自动涵盖其他目标；运行时审批保持原样。更新后使缓存代理在下一轮重建；已在运行的请求不被悄悄改写。

预览采集点在 `AgentLoop` 上下文压缩之后、主模型 `streamMessage` 调用之前。显示系统提示词（含 SOUL、项目指令、项目范围、技能、持久会话上下文）、本次历史消息以及工具定义。它是**应用层输入，不是服务商最终 HTTP 请求体**，也不包括单独的标题生成、摘要生成请求。默认只针对所选主会话，子代理请求不会混到主会话预览里。

预览主动启用一次，五分钟内到期，最多同时保留 16 个会话，每份最多 256,000 字符；截断会明确提示，原始模型输入不因诊断而截断。只保存在进程内存，不新增请求日志文件。脱敏覆盖已配置模型密钥、常见认证字段、Bearer、私钥块与图片内容，但任意正文里未识别的私人信息仍可能保留，分享前需审查。该功能不自动重试模型拒绝，不轮换模型或删除服务边界。

## 已定位问题

`loadRecentMemories()` 曾将 `SOUL.md` 和记忆日志一起加载，导致 SOUL 既位于系统提示词开头，又出现在历史记忆段。现已将该文件排除出近期记忆扫描；测试验证真实调用中人格标记仅出现一次。

应用默认沟通规则现在区分能力询问与操作请求，要求复用已明确的信息、只澄清关键缺口、继续可执行部分，同时保留实际能力和结果核验要求。
