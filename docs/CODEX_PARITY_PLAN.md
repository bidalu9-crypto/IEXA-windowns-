## 1. 最终目标与交付纪律

以已冻结的真实 Codex 桌面端版本为对标对象，完成其全部已核验功能、工具 UI、多代理调度、界面状态和交互动画在 IEXA-WIN 的实现或真实服务集成。保留 IEXA 用户数据、现有多模型能力与已有可用扩展。

- 用户要求是全量验收后一次性交付。后续只汇报进度、证据和阻塞；内部阶段包不再作为完成品交付。
- 既有 `workbench-upgrade-source.zip` 是历史阶段成果，不代表本目标完成。
- “功能一致”“视觉一致”“动效一致”“模型能力/服务依赖”分别核验，任何一项不得被另一项代替。
- 对标版本必须明确平台、版本号、构建号及证据日期。现在只确定目标是 Codex 桌面端，具体构建号待核验；不把 VS Code 扩展或 CLI 的版本当作桌面端版本。
- 在 P0 冻结前，76 项/12 个领域只是候选检查清单，不是官方功能全集。发现遗漏必须增补；确认不属于目标版本的候选项须保留依据，不静默删除。
- 官方账号/托管服务的条目按实际公开接口及运行条件集成，不用假数据、伪成功提示或本地占位页面冒充。
- 不存在有效参考、服务接入条件或测试证据的条目保留未决状态，不标记全量完成。

## 3. 阶段与 oracle

### P0 — 锁定参照，完成全面差距审计（进行中）

交付给内部执行的产物：
1. 目标版本 manifest：平台、版本、构建号、证据来源与时间。
2. 功能矩阵：逐页、逐菜单、逐快捷键、逐设置、逐工具状态核查。
3. 参照图库和录像：主界面、设置、会话、工具卡片、代理视图、弹窗和各类空/加载/异常状态。
4. IEXA 代码审计：入口→前端→API→状态机→执行器→持久化，区分已存在、半实现和缺失。
5. API/账号/云端依赖表以及数据迁移风险清单。

Oracle：每个确认条目有可定位来源、实际行为、验收场景、实现归属；功能清单覆盖参照版本所有可见入口并与文档交叉核对。参照缺失期间允许推进已明确的独立工程基础，但不得声称精确视觉或全功能对齐。

### P1 — 统一执行事件与任务/会话状态机

- 标准事件：任务、会话、工具、父子代理都有稳定 ID、序号、时间和关联关系。
- 明确排队、生成参数、执行、等待审批、等待输入、完成、失败、取消和超时状态。
- 增量参数、输出与执行结果分离；部分 JSON 只展示、不作为完成参数执行。
- 会话切换、断线重放去重、恢复、分支、排队和执行中干预。
- 计划模式与审批必须约束真实执行，而不是只修改系统提示词或 UI 标签。

Oracle：事件重复/乱序/重连测试通过；跨会话隔离；取消传播到实际进程；重启后恢复语义清晰；终态由真实执行结果决定。

### P2 — 编码、审查、回滚与 Git/worktree 闭环

- 核验现有项目指令、技能加载、读取搜索及精确补丁；补齐参照差异。
- 修改前快照，保留编码、换行、权限和用户已有修改；建立变更记录。
- 多文件 diff、逐项审查/接受/撤销、冲突感知回滚和文件跳转。
- Git 状态、提交、分支与任务独立 worktree；审查后集成、冲突处理与回收。
- 真实测试、失败诊断与有界修复，保存命令、输入、输出、退出码。

Oracle：打开夹具项目→读取指导→修改→审查→测试→接受/回滚完整走通；脏工作区、外部修改、重启中断和冲突测试中不丢失用户数据。

### P3 — 真实多代理、后台自动化与外部集成

- 生命周期操作按照参照核验：创建、发送补充输入、等待、关闭、恢复；不是只显示若干角色卡片。
- 独立上下文、工作目录、权限与预算；任务依赖图、并发上限、队列与资源回收。
- 文件写入归属与并发冲突控制；父子事件聚合，结果来源可追踪。
- 父级取消传播、超时/崩溃处理、孤儿回收、重启恢复与预算耗尽行为。
- 后台任务、时区/定时/补跑/幂等、通知和历史。
- MCP、插件、模型适配及参照版本的官方服务按真实接口验证。

Oracle：真实并发执行、同文件冲突、依赖失败、父任务取消、服务重启、预算耗尽等场景通过；父任务不因 UI 卡片已结束就虚报整体完成。集成调用需真实服务证据，mock 仅用于单元/故障测试。

### P4 — 全量 UI、工具 UI、代理 UI 与动效精确对齐

可从 P0 后开始已明确页面；整体状态验收依赖 P1–P3。

- 按参照重新制定布局、图标、文字、色彩、边框、圆角、阴影及缩放规则，收敛样式组件，避免重复追加覆盖样式。
- 工具 UI：参数流入、执行中、结果、日志、diff、审批、取消、错误、重试、附件和大输出；每个可见状态绑定真实事件。
- 代理 UI：创建/排队/运行/等待/结束、父子关系、输入输出、依赖和结果汇总。
- 动效逐项记录：触发条件、起止属性、持续时间、缓动、延迟、方向、变换原点、中断/反向时的行为。
- 采样对象包括按钮、输入区、列表、菜单、弹窗、工具展开收起、流式输出、加载、面板、通知和代理状态转换。
- 除明确记录的 IEXA 品牌差异外，不以“风格接近”“更专业”代替对标检查。

Oracle：冻结版本相同视口/主题/缩放下的逐状态截图对比、动效时序/轨迹对比和实际点击/键盘测试通过。动效期间及结束后的布局均正确；减少动态效果、焦点和读屏路径通过。

### P5 — 综合验收与一次性交付

- 现有回归测试、新增单元/集成测试、真实端到端场景全部运行。

- 路径、权限、插件、IPC 和凭据边界回归；测试不污染真实项目和用户账号数据。
- 干净 Windows 环境构建/安装/启动、升级迁移、卸载与回滚；验证安装包中的资源和运行时代码一致。

Oracle：发布门禁全部满足后，交付源码、安装包、功能对齐报告、视觉/动效报告、测试日志、校验和、迁移说明与回滚方案。源码能编译不是产品验收完成。

## 4. 视觉/动效测量协议

- 先固定目标版本、Windows 渲染环境、窗口尺寸、主题、系统缩放和字体；至少覆盖浅色/深色、常用桌面尺寸、100%/125%/150% 缩放。手机端作为 IEXA 扩展回归，不冒充 Codex 桌面端参照。
- 录制相同输入序列，记录原始视频帧率及时间戳；比较稳定态和过渡态，不只看截图终点。
- 测量容差在 P0 采样后冻结。初始候选为几何误差 1 个逻辑像素以内、动效起止时序误差不超过一个采样帧；这些不是已验证指标，不为通过测试事后任意放宽。

- 每个测试记录参照/实现截图或视频、输入序列、环境、差异及人工复核结论；UI 与实际事件结果双重验证。
